이 문서의 범위 — 사용자 가이드와 무엇이 다른가
PP-APS 사용자 가이드는 화면을 어떻게 쓰는지를 다룹니다. 이 문서는 버튼을 눌렀을 때 안에서 무슨 계산이 어떤 순서로 일어나는지를 다룹니다 — 어떤 테이블의 어떤 행이 어떤 수식을 거쳐 칸의 숫자가 되는지, 경고 한 줄 한 줄이 어느 단계에서 나오는지, 「WO 생성」이 WO 번호·수량·슬롯 시각을 정하는 규칙까지.
모든 수식과 순서는 src/02_Data/AMES.Data/Aps/(순수 엔진)과 Repositories/ApsRepository.cs·PpRepository.Aps.cs(DB 어댑터)의 2026-10-07 소스에서 그대로 옮겼습니다. 예제 숫자는 복제본(98.95.142.192)의 테스트 데이터 — 완제품 83335-P8000 4색(BM1·DNN·JY2·RBQ), 코어 D3133-P8000, 확정 수주 24건 — 로 엔진을 실제 돌려 얻은 값입니다. 손으로 따라 계산할 수 있게 중간값을 전부 적었습니다.

입력 조립 — 조회 한 번에 DB 에서 무엇을 읽어 어떻게 행을 만드는가
1
calendar날짜축 만들기
SYS_FactoryCalendar 를 기준일 −14일 ~ +(일수×2+14)일 읽어 WorkdayCalendar 를 만든다. 행이 있는 날은 DayType 이 WORKDAY·SPECIAL 이면 근무일, 행이 없는 날은 토·일만 휴일. 기준일부터 근무일만 세어 일수만큼 날짜 열을 만든다(휴무일은 열에 없다). 직전 근무일(D-1)과 마지막 날 다음 근무일 전날(수주 읽기 상한)도 여기서 정한다.
예기준일 2026-10-06, 일수 10 → 10/06·07·08·09·13·14·15·16·19·20 (10/10·11 주말, 10/12 공휴일 HOLIDAY 가 빠진다). D-1 = 10/05.
2
settings설정 로드 · 라인 유형
공통코드 APS_SETTING·APS_COVER_TIER 와 MD_ApsLineStage 를 ApsSettingsLoader.Parse 가 Settings + ApsOptions 로 바꾼다(§11). 활성 라인 중 WC ProcessCode 가 INJ → injection, IMG·PNT → assembly. 선택 라인이 사출이면 사출 라인 모드, - 면 전체 완제품 라인 모드, 그 밖은 완제품 라인 모드.
NOTE기준일이 DB 오늘(DbClock.Today)과 다르면 "재고는 현재값 기준" 경고가 먼저 붙는다 — 재고를 과거로 되돌리지 않는다.
3
demand수요 만들기 (DemandRules.Build)
PP_CustomerOrder 에서 상태 Confirmed·Open, 납기 ≤ 상한인 행을 읽고 아래 규칙으로 품번 × 열 배열에 더한다. 「일별 계획 포함」이면 PP_DemandPlan(기준일~마지막 날, 예정량 > 0) 도 같은 배열에 더하되 계획 몫은 PlanDemand 로 따로 보존한다(셀의 "· 계획 N" 표시용).
조건처리
상태가 Confirmed 가 아님제외. 「Open 수주 포함」이 켜져 있으면 Open 도 포함. 그 밖(Closed·Cancelled 등)은 항상 제외
고객 필터가 있고 CustomerID 가 다름제외(경고 없음)
잔량 = OrderQty − ShippedQty ≤ 0제외(경고 없음 — 이미 다 나간 수주)
납기(RequestedDeliveryDate) NULL제외 + 경고 "납기가 없어 잔량 N개를 수요에서 제외"
품번이 활성 MD_Item 에 없음제외 + 경고 "MD_Item 에 없어 … 제외"
납기 < 기준일 (지연 수주)첫날 열에 더한다
납기가 휴무일직전 근무일 열로 접는다. 접힌 날이 기준일보다 앞이면 첫날
납기 > 마지막 날무시(계획판 밖)
일별 계획의 날짜 < 기준일버린다(수주와 다르다 — 지난 계획은 PO 로 바뀌었거나 취소된 것으로 본다)
일별 계획의 PoQty읽지 않는다(저장만). 수요는 ScheduledQty 만
예83335-P8000BM1 수주 6건(10/08·09·13·14·15·16 × 100) → 10일 열에서 demand = [0, 0, 100, 100, 100, 100, 100, 100, 0, 0].
4
candidates후보 품번 → 완제품 행 판정
후보 = 수요가 있는 품번 ∪ 기간 안 WO 슬롯이 있는 품번 ∪ 완제품 재고(WH_Inventory Qty > 0)가 있는 품번. 후보마다:
  • 활성 MD_Item 에 없으면 조용히 건너뜀(수요 품번은 3단계가 이미 경고했다).
  • ItemType = MATERIAL(구매 자재)이면 조용히 제외 — 생산 대상이 아니다.
  • RoutingType NULL 이면 제외 + 경고(이유 병기: 수요 N개 / 재고 N / 등록 계획 있음).
  • 라우팅 템플릿(WorkOrderRepository.ReadPreview)에서 라인이 필요한 단계 중 마지막 단계 = 완제품 공정. 그 단계 라인 = BOP 스테이션 라인 → 없으면 그 공정 활성 라인이 1개일 때 그 라인 → 아니면 경고 후 제외.
  • 완제품 라인이 INJ/IMG/PNT 가 아니면 경고 후 제외. 완제품 라인 모드에서는 선택 라인이 아닌 완제품을 조용히 뺀다(그 라인의 계획이다). 전체 라인 모드는 전부 남긴다.
  • 라우팅에 INJ 단계가 있으면 HasInjStep, INJ 다음의 라인 단계(= 같은 품번 사출품의 "다음 단계 실적" 기준)도 기억한다.
예83335-P8000BM1: RoutingType A = INJ(10) → IMG(20). 마지막 라인 단계 IMG 의 BOP 스테이션 ST-IMG-02 → 완제품 라인 LINE-IMG-02. INJ 단계는 있으나 이 품번 자체의 금형은 없다.
5
injection사출 행 판정 — ① 같은 품번 규칙 · ② BOM 다단계 규칙
완제품마다 사출 자식 목록 (자식, QtyPer) 을 만든다.
① HasInjStep && 활성 MD_MoldItem(완제품 자신) 있음 → 자식 += (자신, 1) // 간선 X→X ② WalkBom(parent = 완제품, mult = 1, depth = 0): for 유효 BOM(APPROVED, EffFrom ≤ 기준일 ≤ EffTo, 부모당 최신 버전) 의 자식 c: q = mult × QtyPer × (1 + ScrapPct/100) c 가 비활성/미등록 → skip c.InjFlag = 1: 활성 금형 있음 → found[c] += q (두 경로로 닿으면 합산) // 여기서 멈춘다 금형 없음 → 경고 "활성 금형이 없어 사출 행을 만들 수 없습니다" (품번당 1회) c.InjFlag = 0: 금형이 있으면 경고 "InjFlag 가 0 이라 사출품으로 보지 않습니다" MATERIAL 이거나 depth ≥ 5 → 더 안 내려감 아니면 WalkBom(c, q, depth+1) // 서브조립 → 한 단계 더 자식 += found 의 순서대로
자식이 하나도 없으면 "사출 단계·활성 금형이 없고 BOM 안에 … 사출 행이 없습니다" 경고(완제품 행은 남고 사출 행만 없다). 사출 라인 모드에서는 이 경고들을 내지 않는다(다른 라인 품번이 섞이므로).
예83335-P8000BM1 BOM: A71573B-SK4655(MATERIAL ×25), D3131-P8000BM1(MATERIAL ×0.125), D3133-P8000(SUB, InjFlag 1, 금형 LQ2RLGDU) ×1 → 간선 (83335-P8000BM1 → D3133-P8000, 1). 4색 모두 같은 코어 → 사출 행은 1개, 간선은 4개.

mold사출 라인 · 금형 · UPH · 캐비티 · 형제 · 포장

7

예BM1 10/06 72 → 수주 T83335-01 라인 10(납기 10/08, 잔량 100) 에서 72 → WO-20261006-001(SoID 1030, Due 10/08, Deadline 10/07). 10/07 104 → 같은 수주 잔량 28 → WO-005(28) + T83335-02 라인 10 에서 76 → WO-006(76, Due 10/09). 10/08 96 → 24(T83335-02 잔량) + 72(T83335-03). 10/09 32 → 28 + 4(T83335-04). 4색 × 7 = 28건.

INJ slots사출 슬롯 — (사출일, 라인, 금형, 색상) 그룹 · 금형 교체 · 주/야 고정 배치
  • 그룹 = 같은 날·라인·금형·색상의 자식 몫들. 그 안에서 다른 자식 품번끼리만 형제(한 shot). 같은 자식 품번이 여러 부모 WO 로 나뉜 조각은 합산한다(차례로 찍는 양). 그룹 시간: 주간분 = MinutesFor(품번별 주간 합 중 최대, UPH), 야간분도 같은 식. MinutesFor = ceil(qty × 60 ÷ UPH).
  • 교대 구간 = 패턴 OPERATING 밴드를 주/야로 나누고 이미 점유된 구간(PM·앞 WO·MC)을 뺀 잔여(ShiftBands.Split).
  • 금형 교체(MC): 직전 금형(그 날 앞 슬롯 → 이전 날짜 마지막 슬롯 → 장착 금형 → 없음)이 다르고 교체시간 > 0 이면, 주간(주간 수량이 있을 때) → 야간 순으로 교체시간 + 1분이 한 빈틈에 들어가는 첫 자리에 MC 를 두고 그 교대 생산은 MC 끝부터. MC 가 야간에 들어가면 주간 생산은 없다(금형이 아직 아니다). 어느 창에도 안 들어가면 MC 도 생산도 쓰지 않고 그 날 전량 Shortfall.
  • 배치: 교대마다 그 교대 수량(PP_ApsPlanLineShift, 없으면 PlanDay/PlanNight 를 첫·둘째 교대로 복원)을 그 교대 잔여 앞에서부터(ShiftBands.SplitByShift → Allocate → SlotPacker.FillDay). 교대 사이를 넘기지 않는다. 기존 슬롯도 교대별로 뺀다(SubtractScheduled: 한 교대 초과분은 다음 교대부터). 모자란 분 = Shortfall. UPH 는 계획과 같은 ApsUph.Effective(2026-10-07).
  • 조각별 슬롯: 대표 품번(ItemNo 순 첫)의 조각은 배치된 구간을 앞에서부터 잘라 실제 슬롯(마지막 조각은 남은 구간 전부 — 형제 몫으로 점유한 시간이 DB 에 남아야 능력이 맞다). 구간마다 수량 = 구간 길이 × UPH 내림, 다 실었으면 마지막 구간이 나머지 전부. 형제 품번 조각은 대표 교대 첫 슬롯 시작의 0분 슬롯(StartMin = EndMin)에 수량만, MoldID 없음. 조각마다 PP_ApsRunWo 1행(Qty = 자식 단위).
예 (실행 #1, LINE-INJ-02 10/06)직전 금형 없음 ≠ LQ2RLGDU, 교체 30분 → 주간 첫 빈틈 450 에 MC 450–480. 4 조각 × 72 = 288 → 각 36분(72 × 60 ÷ 120): WO-001 480–516 · WO-002 516–552 · WO-003 552–570 + 580–598(휴게 570–580 을 건너뛰어 두 구간) · WO-004 598–634. 전부 주간, Shortfall 0.

FG slots완제품 단계 슬롯 (DeadlinePacker) · 상태 마감
조각마다 완제품 단계(IMG/PNT)를 DeadlinePacker.Pack 으로 배치: 오늘 = 사출일, 시작 = 그 그룹 INJ 슬롯의 축상 끝, 마감 = ProdDeadline, 납기 = DueDate. 배치량 = 그 조각이 사출에 실제로 실은 수량(모든 자식의 실적 ÷ QtyPer 최소, 내림) — 사출이 0 이면 완제품 슬롯도 없다. 슬롯은 박스 단위(완제품 BoxQty, 없으면 ROUND_TO — 2026-10-07 사용자 결정): 틈마다 온박스만 싣고(8개들이 · 90초 = 12분) 한 박스 분이 안 되는 틈은 건너뛴다. FIFO 로 갈라진 부분 박스(28 = 3박스 + 4)는 마지막에 한 번 — 남은 온박스가 다 들어가는 틈이면 같은 슬롯에 붙고, 아니면 자기 분만큼의 틈을 따로 찾는다. PP-003 의 같은 배치기는 종전대로 개 단위다. 마감일까지 못 넣으면 납기일까지 Late, 그래도 남으면 Shortfall. 슬롯은 전부 DRAFT(게시는 PP-LSB). PITFALL
일수가 짧으면 끝이 잘린다
현상
마지막 날은 기준수요 0 이라 수요만 채우고, 계획판 밖 수주는 아예 안 보인다. 실행 #1(5일)의 10/09 사출 128 vs 10일 조회 416.
대처
일수 = 마지막 납기까지 + 선행일 + 커버 며칠. WO 는 앞쪽 날짜만 고르면 된다.
PITFALL
BoxQty NULL
현상
사출 행 포장 1 → 1개 단위로 올림(박스 개념 없음) + 경고. 완제품 전용 행은 ROUND_TO(5). BOM 규칙 WO 수량도 ROUND_TO 로 올림.
대처
MD-003 박스 수량 입력. 복제본은 4색 + 코어만 8 이고 나머지는 NULL(수요 없어 무해).
LIMIT
패밀리 금형 UPH — 계획 60 vs 슬롯 120
현상
계획은 캐비티 분할 UPH, WO 슬롯은 MD_MoldLine 원값. 형제 없이 한 품번만 발행하면 슬롯 시간이 절반(§09 노트).
대처
코드 과제. 그때까지는 패밀리 금형 품번의 PP-LSB 슬롯 길이를 의심하고 본다.
LIMIT
PM 밴드 · 금형 교체 1회 · 0분 마커
내용
화면 능력은 PM 을 안 빼고 WO 생성만 뺀다 → 화면 OK 가 생성에서 Shortfall 가능. 같은 라인·날·금형 그룹당 MC 최대 1개(되돌림 교체 없음). PP-LSB 에서 대표 슬롯을 지워도 형제 0분 행은 남는다.
INFO
조회 결과 첫 화면에 사출 칸이 빨갛다
뜻
자동 계산 전에는 사출 계획이 등록 슬롯뿐이라 소요 > 계획 → remain 음수 → short. 「계획 자동 계산」을 누르면 사라진다. 눌러도 남으면 능력 경고를 본다.
INFO
같은 날 두 번째 실행에서 WO 가 또 나온다
뜻
첫 실행 슬롯은 잠긴 칸으로 들어오므로 보통 추가 공급 0. 잠금을 풀었거나 일수를 늘려 새 수요가 보이면 그만큼 추가 발행된다. 이중 발행 방지는 "기존 슬롯 수량 차감" 이지 "같은 수주 재발행 금지" 가 아니다 — FIFO 잔량은 기발행 WO 를 빼므로 수주를 넘기면 SoID NULL 재고 보충 WO 가 된다.
