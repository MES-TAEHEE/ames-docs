# 라인 위치(로케이션) 테스트 가이드 — TST 라인

대상 시나리오: `scenarios-a.js` 의 **MD-06-L1 · MD-06-L2 · MD-06-L3 · MD-09-U2 · MD-06-L4** (MD-09-U 는 그대로 두고 MD-09-U2 로 이어서 확인)
작성일: 2026-11-12

## 1. 무엇이 문제였나

### 1-1. 설계는 있었다
`CLAUDE.md` 의 LOT 접두어 항목에 "라인 로케이션·WH_AREA 코드는 **라인 등록 때** 생겨"라고 적혀 있다. 즉 라인을 등록하면 라인 위치와 라인 구역 코드가 함께 생기는 것이 설계다.

### 1-2. 구현이 빠져 있었다
- MD-001 라인 등록(`MasterDataRepository.InsertLine`)은 `MD_Line` 행만 만들었다. 라인 위치(`MD_Location`)와 구역 코드(`MD_CodeItem` 의 `WH_AREA_<접두어>`)는 만들지 않았다.
- 지금 있는 라인 위치·구역 코드는 예전 데이터 이관으로 만들어진 것이다. 그래서 기존 라인은 보였지만, 이번 테스트에서 새로 만든 TST 라인은 MD-018 과 로케이션 지도에 나오지 않았다.
- 따라서 **설계는 되어 있었고, 구현이 제대로 안 되어 있었다**가 맞다.

### 1-3. 수정 중 생긴 문제 (같은 작업에서 고침)
- 위치 행을 자동으로 만들게 되자, 라인 삭제 전 사용처 검사가 빈 자동 위치 행을 "사용 중"으로 보았다. 그래서 사용하지 않는 임시 라인(MD-06-D 의 LINE-TMP-01)도 지울 수 없게 됐다.
- 사용처 검사를 고쳐서 **재고·하위 위치·품번이 있는 위치만** 막도록 했다. 빈 자동 위치 행은 라인을 지울 때 같이 지운다.

### 1-4. 이름 변경은 원래 동작한다
라인 이름을 바꾸면 위치 이름과 구역 코드 이름도 같이 바뀐다. 기존 `UpdateLine` 에 이미 구현되어 있었다.

## 3. 테스트 준비

1. VS Code 에서 Web 디버그 세션을 **중지**하고 `AMES.Web` 을 다시 빌드·실행한다. (실행 중인 Web 은 옛 빌드라 변경이 안 보인다.)
2. 브라우저를 강력 새로고침(Ctrl+F5)한다.
3. 로그인 계정은 MD(기준정보) 편집과 WH(로케이션 지도) 편집 권한이 있어야 한다.
4. TST 라인 3개(LINE-INJ-TST, LINE-IMG-TST, LINE-PNT-TST)가 MD-001 에 있는지 먼저 확인한다.

### 3-1. DB 확인 쿼리 (SSMS, 읽기 전용)
연결: 서버 `localhost\SQLEXPRESS`, 데이터베이스 `AMES_DEV`

```sql
-- ① 라인 위치: TST 라인과 임시 라인
SELECT LocationID, LocationName, AreaCode, LocationType, LineID, ActiveFlag,
       LocationLevel, ParentLocationID, Aisle, Bay, Slot, WhCode, Capacity, PartNo, MinimumQty
FROM dbo.MD_Location
WHERE LineID IN ('LINE-INJ-TST','LINE-IMG-TST','LINE-PNT-TST','LINE-TMP-01');

-- ② 라인 구역 코드
SELECT CodeID, CodeValue, CodeName, ParentCodeID, UseFlag
FROM dbo.MD_CodeItem
WHERE GroupCode = 'WH_AREA' AND CodeValue IN ('IT','WT','PT','T1');

-- ③ 라인 마스터
SELECT LineID, LotPrefix, LineNameEn, Status
FROM dbo.MD_Line
WHERE LineID IN ('LINE-INJ-TST','LINE-IMG-TST','LINE-PNT-TST','LINE-RWK-01','LINE-TMP-01');
```

### 3-2. 임시 라인 정리 (테스트가 끝나지 않고 멈췄을 때만)
LINE-TMP-01 이 남아 있으면 MD-001 에서 삭제한다. 삭제가 안 되면 아래 순서로 DB 에서 직접 지운다(재고가 없는 임시 데이터에만 사용).

```sql
DELETE dbo.MD_Location WHERE LocationID = 'T101A1F1' AND LocationType = 'LINE';
DELETE dbo.MD_CodeItem WHERE CodeID = 'WH_AREA_T1';
DELETE dbo.MD_Line     WHERE LineID = 'LINE-TMP-01';
```

## 4. 시나리오 순서

| 순서 | ID | 화면 | 확인할 것 | 예상 결과 |
|---|---|---|---|---|
| 1 | MD-06-L1 | MD-001 라인 + DB 확인 | 라인 등록 때 위치·구역 코드 자동 생성 | 라인 3개 각각 위치 1행, 구역 코드 1행. 재작업 라인은 위치 없음 |
| 2 | MD-06-L2 | MD-018 로케이션 마스터 | TST 라인 위치가 목록에 보이는지 | IT01A1F1 · WT01A1F1 · PT01A1F1 표시, 유형 LINE, 상위 미지정 |
| 3 | MD-06-L3 | WH 로케이션 지도 | 라인 구역 목록에 TST 라인이 나오는지, 검색 이동 | 라인 구역 3개, 칸 1개씩, 검색 결과 선택 시 이동·선택 |
| 4 | MD-09-U2 | MD-018 행 팝업 (MD-09-U 이어서) | 공급 파트 자동 표시, 이름·용량·최소 수량 저장 | 아래 4-1 참조 |
| 5 | MD-06-L4 | MD-001 라인 + DB 확인 | 사용처 없는 임시 라인 삭제 시 위치·구역 코드도 삭제 | 라인·위치 T101A1F1·구역 WH_AREA_T1 모두 없어짐 |

**주의**: MD-06-L4 는 반드시 마지막에 한다. TST 라인은 MD-11(설비), MD-13(슈퍼바이저) 시나리오가 쓰므로 지우면 안 된다.

### 4-1. MD-09-U2 세부 값
- 대상: `IT01A1F1` (LINE-INJ-TST)
- Assigned Parts 자동 표시 기대값: ST-INJ-TST 의 BOP 품번 **TST-CORE-A, TST-A-001-LH, TST-A-001-RH, TST2-CORE-B** (직접 고르지 않는다)
- 이름: `Injection Line Test (MD-09-U)`
- Load Capacity: `500`
- 파트별 최소 수량: TST-CORE-A `10` (나머지 파트는 그대로)
- 저장 후: MD-018 목록 새로고침 → 행을 다시 열어 값 유지 확인
- 지도: WH 로케이션 지도에서 IT 라인 구역 → 칸 이름·상세 창이 바뀐 값과 맞는지 확인
- 경고: Load Capacity 를 현재 재고보다 작게 낮추면 경고와 확인 창이 나와야 한다. 라인 위치에 재고가 아직 없으면 경고가 안 나올 수 있다(재고 준비 후 다시 확인).
- DB 확인: 쿼리 ①에서 `IT01A1F1` 의 `LocationName`, `Capacity`, `MinimumQty` 값(또는 파트별 최소 수량 행)을 대조

## 6. 확인하지 못한 것 / 남은 질문

- **화면 확인**: 이 문서를 만들 때 Web 화면은 실제로 확인하지 못했다(실행 중인 Web 이 옛 빌드). 3번 준비 후 시나리오로 확인해 달라.
- **재고 있는 라인 위치 삭제 거부**: 위치에 재고를 올린 뒤 삭제가 막히는지는 아직 시험하지 않았다. 재고를 올리는 방법(테스트 데이터)을 정해야 한다.
- **정책 변화**: 사용처가 없으면 기존 라인(예: LINE-INJ-01)도 이제 삭제할 수 있다(그 라인의 빈 위치도 같이 지워진다). 기존 라인도 그렇게 두는 것이 맞는지 확인이 필요하다.
- **상위 로케이션 연결**: 신규 라인 위치는 상위 로케이션이 없다. 기존 라인은 `TMP-LINE` 아래에 있다. 같은 상위에 묶을지 정해야 한다.
- **커밋**: 위 코드 변경과 시나리오·가이드 문서는 아직 커밋하지 않았다.
