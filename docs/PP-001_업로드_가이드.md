# PP-001 업로드 가이드 — 예측 · 일별 구매계획 · 구매오더 · 일별 발주

Written for: 구매계획 담당자(PLAN Manager)와 SRM 파일을 고쳐 올리는 사용자.

이 문서는 SRM 에서 받은 파일을 AMES 에 올리는 방법을 설명합니다. 올리는 양식마다 **샘플 파일을 화면에서 받아** 같은 모양으로 고쳐 올리면 됩니다.
샘플은 같은 데이터에서 만들어져 서로 일치합니다(구매오더 납기별 합 = 일별 발주 = 구매계획 P/O).

## 한눈에 보기

| 양식 (SRM) | 화면 · 버튼 | 샘플 받기 | 저장 방식 | 쓰이는 곳 |
|---|---|---|---|---|
| 구매오더 MM31006 (발주번호별) | PP-002 수주 「엑셀 업로드」 | 업로드 창의 「샘플 다운로드(구매오더)」 | 수주 행 갱신·추가 | 수주 잔량 → APS·WO |
| 일별 발주 MM31007 (납기일자별) | PP-001 「일별 발주·대조」 탭 「엑셀 업로드(일별 발주)」 | 같은 탭 「샘플 다운로드(일별 발주)」 | 고객 × 날짜 창 교체 | 대조 탭 |
| 일별 구매계획 MM30011 | PP-001 「일별 구매계획」 탭 「엑셀 업로드(일별)」 | 같은 탭 「샘플 다운로드(일별)」 | 고객 × 날짜 창 교체 | APS 수요, **예측 현황(주 합산)** |

**예측 현황은 업로드하지 않습니다.** 일별 구매계획을 월요일 시작 주로 합산해서 보여 줍니다. 주간 예측 파일(ZMM30004)은 더 이상 쓰지 않습니다.

**권장 순서**: ① 구매오더 → ② 일별 발주 → ③ 일별 구매계획 → ④ 「일별 발주·대조」 탭에서 차이 확인.

**고객**: 서현이화 3곳만 선택합니다. SAV(Savannah, `CUS-SAV`), GEO(Georgia, `CUS-GEO`), AUB(Auburn, `CUS-AUB`).

## 공통 규칙

- 파일 형식: SRM 에서 받은 `.xls`(HTML 표) 또는 `.xlsx` 모두 됩니다. 샘플은 `.xlsx` 로 받습니다.
- **구매오더·일별 발주는 열을 머리글 이름으로 찾습니다.** 열 순서가 바뀌어도 되지만 머리글 글자는 바꾸지 마세요. 영문·국문 머리글 모두 인식합니다(예: `발주량` = `P/O Qty`).
- 날짜 머리글이 두 열을 덮는 병합 모양(일별 발주)은 샘플과 같이 두세요.
- 올린 뒤에는 미리보기의 **품번 수 · 기간 · 칸 수**와 **업체 코드 대조 결과**를 확인하고 저장합니다.
- 「MD_Item 에 없는 품번」 경고는 저장을 막지 않습니다. 품목 마스터(MD-003)에 등록한 뒤 다시 올리세요.

## 1. 구매오더 MM31006 (PP-002 「엑셀 업로드」)

- **필수 열**: `발주번호`(또는 `P/O No.`), `PART NO`, `납기일자`(또는 `ArrReq. Date`), `발주량`(또는 `P/O Qty`)
- **선택 열**: `업체`, `업체명`, `발주일자`, `품명`, `발주단위`, `납품수량`
- **발주번호**: `4100181400-10` 처럼 `수주번호-라인`. 마지막 `-` 뒤가 라인 번호입니다.
- **날짜**: `yyyy-MM-dd`. `0000-00-00` 은 비어 있는 것으로 봅니다.
- **제외되는 행**: 발주번호에 숫자가 없는 행(합계·보조 표), 발주량이 음수인 행(반품 — 미리보기에 제외 건수 표시).
- **저장**: 같은 고객·수주번호·라인은 갱신하고, 없으면 새로 만듭니다. 새 행의 상태는 PP-002 「자동 확정」 설정을 따릅니다.
- **취소 처리(기본 체크)**: 미리보기에 「파일에 없는 수주 N건을 취소 처리」가 나오면 **기본으로 체크되어 있습니다.** 이 고객·파일 납기 범위 안에서 파일에 없고 아직 출하가 없는 Open·Confirmed 라인을 `Cancelled` 로 바꿉니다.
  - **파일이 그 기간의 전체 목록일 때만 체크를 둡니다.** 일부 품번만 담긴 파일이면 체크를 해제하세요.

## 2. 일별 발주 MM31007 (「일별 발주·대조」 탭)

- **필수 열**: `PART NO`, `발주단위`, `적입량`
- **날짜 열**: 머리글에 `MM-dd`(예: `11-03`, 연도 없음). **날짜마다 두 열**이 한 쌍입니다 — 첫 열은 머리글 `발주량`, 다음 열은 `납품량`(두 열 모두 날짜 머리글 아래).
  - 연도는 기준일의 연도로 붙입니다. 기준일보다 6개월 넘게 지난 날짜는 다음 해로 봅니다.
- **선택 열**: `업체`(협력사 코드 대조에 쓰임), `업체명`, `품명`, `저장위치`, `고객사`, `구매오더유형`, `차종`
- **저장**: 고객 · 날짜 창 전체를 다시 씁니다. 같은 품번이 여러 줄이면 날짜별로 합칩니다.

## 3. 일별 구매계획 MM30011 (「일별 구매계획」 탭)

- **구조**: 고정 열 12개(`NO`·`Vendor Code`·`Vendor Name`·`Car type`·`PART NO`·`PART NAME`·`Unit`·`Packing Qty.`·`D-1`·`Basic Inv`·`Current Inv`·`Open Order Qty`) + `Sub total` 2열 + 날짜마다 2열.
- **1행(머리글)**: 날짜는 `yyyy-MM-dd`, 첫 열부터 하루씩. **2행(라벨)**: 날짜마다 `Scheduled Qty.`·`P/O Qty.`.
- **Vendor Code**: 샘플은 고객 설정의 협력사 코드(VENDCD)로 채워집니다. 고객을 고르고 샘플을 받으세요.
- **예정량(Scheduled)** 이 APS 수요와 예측 현황(주 합산)에 쓰입니다. P/O 는 참고입니다.
- **적입량(Packing Qty.)**: MD-003 적입수량과 다르면 미리보기에 경고가 나옵니다.

## 4. 예측 현황 (파생 — 업로드 없음)

- 「예측 현황」 탭은 **일별 구매계획(MM30011)을 월요일 시작 주로 합산**합니다. 값을 따로 올리지 않습니다.
- 고치려면 일별 구매계획을 고치고 다시 올리세요.

## 5. 대조 (「일별 발주·대조」 탭)

고객과 기간을 고르고 「조회」를 누르면 아래 차이만 보입니다. 같은 수요를 가리키는 값은 같아야 합니다.

| 차이 종류 | 뜻 | 확인할 것 |
|---|---|---|
| 수주 발주량 ≠ 일별 발주(MM31007) | 같은 품번·납기일인데 수량이 다름 | 구매오더를 다시 받았는지, 일별 발주 파일이 같은 시점인지 |
| 수주는 있는데 일별 발주 없음 | 구매오더에 있는 납기일이 일별 발주에 없음 | 일별 발주 파일의 기간·품번 범위 |
| 일별 발주는 있는데 수주 없음 | 일별 발주에만 있음 | 구매오더 파일 누락 또는 취소 |
| 일별 발주 ≠ 구매계획 P/O(MM30011) | 같은 날 P/O 수량이 다름 | 두 파일의 시점 |

- 대조는 **조회할 때** 계산합니다. 일별 발주를 올리면 탭이 그 고객·기간으로 자동 조회됩니다.

## 6. 업체 코드 대조 (협력사)

- 구매오더·일별 발주 파일의 `업체` 코드는 **고객의 SRM 설정**(SW_POSYNC_SOURCE · SW_DPSYNC_SOURCE 의 설명란 `VENDCD=`)과 맞아야 합니다.
  - **맞음**: 미리보기에 「협력사 코드 … 일치」.
  - **다름**: 「협력사 코드 … 다릅니다」 — **업로드 차단**. 다른 고객의 파일이거나 설정이 잘못된 것입니다.
  - **설정 없음**: 「협력사 설정(VENDCD)이 없어 대조하지 않았습니다」 — 경고만 하고 진행합니다.
- 샘플을 받을 때 고객을 먼저 고르면 그 고객의 VENDCD 가 샘플에 들어갑니다. 고르지 않으면 `SAMPLE` 로 들어가고, 그 샘플은 고객 설정이 있으면 차단됩니다.
- 샘플 종류별 업체 코드: 구매오더·일별 발주·일별 구매계획 모두 선택한 고객의 VENDCD 를 씁니다.

## 7. 자주 나는 오류

| 메시지 (요지) | 원인 | 조치 |
|---|---|---|
| 필수 열이 없습니다: … | 머리글 이름이 바뀌었거나 빠짐 | 샘플의 머리글 이름과 맞추기 |
| 날짜 머리글 '…' 을 읽을 수 없습니다 | 일별 발주의 날짜가 `MM-dd` 가 아님 | 날짜를 `11-03` 형식으로 |
| 발주량 바로 다음에 납품량 열이 없습니다 | 날짜 쌍이 깨짐 | 날짜마다 `발주량`·`납품량` 두 열 확인 |
| 협력사 코드 … 다릅니다 | 고객 선택 또는 파일이 다름 | 고객과 파일을 다시 확인 |
| … 을 숫자로 읽을 수 없습니다 | 수량 칸에 글자·공백 | 숫자 칸 정리 |
| 파일에 없는 수주 N건 … | 취소 처리 체크 상태 | 전체 목록이 아니면 체크 해제 |
| 품번 … 은 MD_Item 에 없어 … | 품목 마스터에 없음 | MD-003 에 품목 등록 후 다시 올리기 |

## 8. 샘플로 올리는 절차

1. 업로드할 고객을 고릅니다(샘플의 업체 코드가 그 고객 설정으로 채워지도록).
2. 샘플을 받습니다.
3. 실제 데이터로 고칩니다. **머리글 글자와 날짜 쌍 구조는 그대로 두세요.**
4. 같은 화면에서 올립니다.
5. 미리보기의 품번 수·기간·업체 대조를 확인한 뒤 저장합니다.
6. 「일별 발주·대조」 탭에서 차이를 확인하고, 예측 현황 탭에서 주 합계를 봅니다.

## 9. 현재 구현의 제한

- **일별 구매계획(MM30011)은 아직 고정 위치로 읽습니다.** 이 양식이 바뀌면 파서를 고쳐야 합니다. 구매오더·일별 발주는 머리글 이름으로 읽습니다.
- 수주 **변경 이력**은 남지 않습니다(값이 바뀌면 덮어씁니다). 취소 처리만 있습니다.
- `.xlsx` 의 병합 셀은 펴지 않습니다. SRM 이 주는 `.xls` 는 펴서 읽습니다.
- 예전에 올린 주간 예측 데이터(PP_Forecast)와 그 이력은 DB에 남아 있지만 화면에서 쓰지 않습니다.

## 10. 업로드 후 화면이 어떻게 반영되는지 (11-03 변경)

- **적용 순서**: 같은 고객·품번·날짜는 **수주(구매오더) > 일별 발주(MM31007) > 일별 구매계획(MM30011)** 순서로 한 번만 셉니다. 예측 현황, 일별 구매계획, APS 수요가 같은 규칙을 씁니다. 그래서 어느 파일을 올려도 중복 없이 같은 숫자로 보입니다.
- **업로드 이력은 한 곳**: 「업로드 이력」 탭 하나에서 구매오더·일별 발주·일별 계획(·이전 주간)을 모두 봅니다. 종류 열로 구분합니다.
- **업로드 후**: 예측 현황·일별 구매계획·일별 발주·대조·업로드 이력이 모두 다시 읽힙니다. 올린 고객과 기간으로 필터가 맞춰집니다.
- **대조 탭**: 고객을 고르지 않으면 **전체 고객**을 보여 줍니다. 고객 열이 함께 나옵니다.
- **구매오더 업로드 기록**: 업로드마다 신규·갱신·취소 건수가 이력에 남습니다(`PP_ImportBatch`).
- 배포 전 DB에 `dist/migrate_pp_import_batch.sql` 이 필요합니다. 없으면 구매오더 업로드 뒤 기록이 실패합니다.
