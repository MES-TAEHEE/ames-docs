## DB 스키마 영역

|--------|------|

**품목·BOM 정본은 `docs/260828 BOM Master List.xlsx`** 이고(09-28), `tools/gen_md_item_bom_seed.py` 가 그 엑셀을 읽어 `dist/seed_md_item_bom_master_list.sql` 을 만든다 — 생성물이라 손으로 고치지 말고 엑셀·생성기를 고쳐 다시 만든다. 시드는 `MD_Item`·`MD_BomVersion`·`MD_Bom`·`SCM_ItemVendor` 를 **전부 지우고** 넣으며(SEMS 추출분 등 엑셀에 없는 품목은 사라진다 — 사용자 결정), 품목·BOM 을 **FK 로** 참조하는 행이 있으면 시작 전에 THROW 하므로(FG 테이블 구성이 DB 마다 달라 이름이 아니라 `sys.foreign_keys` 로 찾는다 — FK 없는 수주·WO·LOT·재고·반품 참조는 검사하지 않고 고아로 남는다. 마지막 FK `FK_FG_CustomerReturn_Item` 은 09-30 `dist/migrate_drop_fg_customer_return_item_fk.sql` 로 없앴고 스키마·`PDA_SCHEMA.sql` 도 더 이상 만들지 않는다) `rebuild_db.sh` 순서(PDA_SEED 이전, 구 `reseed_md_item_partmaster.sql` 자리)로 적용하거나, 운영 중인 DB 에는 `dist/run_seed_md_item_bom_master_list.sql`(저장소 루트에서 `sqlcmd … -I -b -v Mode=ROLLBACK|COMMIT`, 트랜잭션 하나)로 단독 적용한다. 규칙: ItemNo = 품번 + 3자리 색상(루트는 Assembly Color 마다 1행, 자식은 Material Color 가 조립색별로 다르면 같은 순번 색·단일 색이면 그 색·BK/공란이면 무접미) · RoutingType 은 Complete ASSY = `'A'`(코어 사출 → 완제품 IMG), 그 밖은 NULL · ItemType 은 Complete ASSY = ASSY / 공급사 `MIP.JACKSON`(자사) = SUB / `LP.`·`KD.` 구매 = MATERIAL(단위 G·SH 는 항상 MATERIAL) · ItemCategory ASSY→TRIM, SUB→SUB, MATERIAL→FABRIC(SH)·RESIN·CHEM·FASTENER·PART(뒤 4개는 시드가 공통코드로 추가) · CarType 은 `■` 헤더(NE1A W 는 NE1A, 공용 자재는 NULL) · PGN·ALC 는 엑셀에 없어 생성기에 박아 둔 09-24 개발 DB 스냅샷을 되살린다(IMG 라벨용, MountPos 는 없음) · Material Spec·중량·사이즈는 컬럼을 추가하지 않고 버린다(사용자 결정) · BOM 은 부모 품번마다 `V-{ItemNo}-01`(APPROVED, EffFrom 2026-08-28) 1건 + 직접 자식 Level 1, QtyPer = Usage Quantity 변형 열(BB=1번·BC=2번 루트), 구매 부품(MATERIAL) 아래 레진은 사급이 아니라 넣지 않는다(사용자 결정) · 공급사 8곳은 `MD_Vendor`(LP → LOCAL, KD → CKD) + `SCM_ItemVendor`, 단위 `SH` 는 `MD_Uom` 에 추가. 원본 보정(루트 오기 3건 `M3320-PI020`·`M2320-QI000`·`M2320-FC000`, `YUG→YGU`, LQ2 +CUR 루트 P8010 유도, 조지아 NQ5a·MV1a 의 품번 없는 행·`?` 수량·복사 잔재 제외)은 생성 SQL 머리말에 전부 나열된다. 구 시드 `reseed_md_item_partmaster.sql`·`seed_md_item_tailgate_door_trim.sql`·`seed_md_bom_tailgate_door_trim.sql`·`fix_md_item_seed_align.sql` 은 더 이상 쓰지 않는다.

LotNo 채번 기반(`SYS_LotSeq` · `MD_Line.LotPrefix` · `tbl_Lot.LotCode` 유니크 인덱스)은 `dist/migrate_lotno_rule.sql` — INJ 원천 Lot 과 실적 배치 Lot(`ProductionRepository.RecordCycle`, IMG-03 등)은 9자리 신규칙(`[년1][월1][일1][라인코드2][순번4]`, 년=A~Z 26년 순환)으로 `LotNoGenerator` 가 채번하며, `LotPrefix` 미등록 라인은 채번이 예외로 막힌다 (스키마 시드: INJ I1~I9 / IMG W1~W5 / PNT P1·P2, 공장 `EOS-PLT-01` — 개발서버 MD_Line 기준). **LOT PREFIX 는 LOT 을 발행하는 공정(사출·감싸기·도장)의 라인만 필수이고 재작업 등은 두지 않는다**(10-23 사용자 결정, 규칙 정본 `AMES.Data.Services.LotPrefixRules`, 테스트 `LotPrefixRuleTests`): MD-001 라인 화면은 고른 작업장의 공정에 따라 입력칸을 필수/꺼짐으로 바꾸고, 저장소 `InsertLine`·`UpdateLine` 은 LOT 공정 라인에 접두어가 없으면 52079 로 거부하며 다른 공정 라인의 접두어는 받지 않는다(`LotPrefixGuardSql`). WO 릴리스 후보(`WorkOrderRepository.ReadPreview`)는 접두어 없는 LOT 라인을 후보·BOP 라인에서 빼고(`RoutingStepPreview.NoPrefixLines`) 지정하면 `LotPrefixMissingException` 으로 거부하며, PP-003 은 그 수주를, PP-APS WO 생성은 그 사출 행을 `RejectNoLotPrefix` 로 거부한다(APS 는 거부가 있으면 WO 를 만들지 않는다). **이미 쓰인 접두어는 바꿀 수 없다**(10-23 사용자 결정) — 쓰임 = 그 라인 LOT 번호의 4~5번째 글자·채번 헤더(`SYS_LotSeq.Header` 4~5번째)·라인 재고 위치(`WH_Inventory.LocationNo`, `BF-` 자리표시 포함) 중 하나라도 있음(`MasterDataRepository.LotPrefixUsedSql`; 라인 로케이션·`WH_AREA` 코드는 라인 등록 때 생겨 기준에서 뺐다). MD-001 수정 창은 `LotPrefixInUse` 로 입력칸을 끄고 안내(`MD.Line.Hint.LotPrefixLocked`)를 보이며, `UpdateLine` 은 라인 행을 UPDLOCK 으로 잡고 다른 값이면 52080 으로 거부한다(같은 값·다른 칸·작업장 변경은 통과). 52078·52079·52080 은 화면에서 다국어 문구(`MD.Line.Err.LotPrefix*`)로 보인다. 정본 테스트 `LotPrefixRuleTests.Used_prefix_cannot_be_changed`(로컬 DB 쓰기). 바꿔야 할 때의 관리자 SQL 은 아직 없다(확인사항).

BOM: 한 행 = 버전 정보 + 구성 라인 하나(라인 없는 버전은 구성품 칸을 비운 행, 상태 열은 참고용) — 없는 버전은 DRAFT 로 만들고 라인을 넣고, 있는 초안 버전엔 없는 구성품만 더하며, 초안이 아닌 버전은 통째로 건너뛴다. 새 버전은 화면 등록과 같이 시작일 필수·오늘부터, 구성품은 있는 품번·자기 자신 아님·순환 없음·수량 > 0(단위 열은 내려받기 참고용 — 올리면 읽지 않고 구성품 기본 단위로 저장, 10-23), **한 버전에 문제가 하나라도 있으면 그 버전은 등록하지 않는다**(반쪽 BOM 방지). 버전 등록은 `MasterDataRepository.ImportBomVersion`(버전 행 UPDLOCK·버전 + 라인 한 트랜잭션, 그사이 생기거나 초안이 아니게 된 버전은 null, 테스트 `BomImportDbTests` 로컬 DB 쓰기). 감사는 등록마다 Created(초안에 라인만 더하면 `MD-004/IMPORT`), 품목은 끝에 `MD-003/IMPORT` 요약 1행. 파일 읽기·쓰기는 외부 패키지 없는 `Services/XlsxSheetReader`·`XlsxWriter`(첫 시트만, 최대 10MB).
