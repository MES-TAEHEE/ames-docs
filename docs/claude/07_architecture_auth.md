## 아키텍처 원칙

### 시각 기준 — DbClock
- 기록 시각의 정본은 DB 서버 시각(`SYSDATETIME()`, 공장 현지시각 — 개발서버는 미국 동부시간)이다. 화면 기본값·"오늘" 필터·채번 접두어에 **`DateTime.Now`/`DateTime.Today` 를 쓰지 말고 `DbClock.Now`/`DbClock.Today`**(`AMES.Data.Services.DbClock`, Web 은 `GlobalUsings.cs` 의 전역 별칭)를 쓴다.
- `DbClock` 은 DB 시각 − 호스트 시각(Offset)을 한 번 읽어 두고 `DateTime.Now + Offset` 으로 계산한다(호출마다 DB 를 가지 않음, Kind=Unspecified). `AMES.Contracts` 는 DbClock 을 참조할 수 없어 `WorkOrderDto.DaysToDue`(PP-004·PP-CAL·POP 작업지시 팝업의 D-day)의 "오늘"은 정적 공급자 `WorkOrderDto.Today` 이고 Web 기동 때 `DbClock.Today` 로 지정한다(10-13). Web 은 기동 시 `Program.cs` 가 1회, 로그인(회로 시작) 때 `TopBar` 가 10분보다 오래됐을 때만 다시 맞춘다. PP-LSB 는 Now 선 때문에 1분 기준. 상태는 `GET /api/health` 의 `dbClock`(now·offsetMinutes·syncAgeSec)로 확인한다.
- **POP 도 10-15 부터 DbClock 을 쓴다**(사용자 결정 — PP-003·PP-LSB 가 DB 날짜(복제본은 UTC)로 놓은 오늘 슬롯을 EDT 터미널이 호스트 날짜로 읽어 저녁 20~24시에 INJ-MAIN PLAN 이 0 이던 문제): `PopServices.Initialize` 가 `Configure`, 로그인 화면이 뜰 때 백그라운드 + 로그인 성공 때 `EnsureSynced(10분)`. INJ/IMG-MAIN 의 "오늘"·달력 최대값·REWORK·QC·PNT 의 시계·안돈 경과·라벨 발행일(IMG)·스캔 이력 시각이 전부 `DbClock`(전역 별칭 `GlobalUsings.cs`)이고, 유휴 만료(`IdleWatcher`)·로그 파일명(`PopLog`)·토스트는 호스트 시계 그대로다. 정본 테스트 `DbClockTests`(AMES_DEV 필요).
- `Configure` 하지 않은 프로세스(API)와 동기화에 실패한 프로세스는 Offset 0 = 호스트 시계 그대로다. 웹과 DB 가 같은 기계면 Offset 은 0 에 가깝고, 한국시간 PC 의 로컬 IIS + 개발 DB 조합에서는 −780분이 정상이다.

### Repository 패턴
- 모든 DB 접근은 `AMES.Data.Repositories.*Repository` 경유
- 각 메서드마다 `using var conn = _connFactory.OpenConnection()` (connection-per-method)
- `MapToDto()` static 헬퍼로 `SqlDataReader` → DTO 변환
- 향후 `dbo.SP_*` 스토어드 프로시저로 전환 예정 (현재 inline SQL)

### Pop 모듈 분기
로그인 화면에서 작업자가 Line/Station을 선택하면, 선택 라인의
`MD_Line.WCID → MD_WorkCenter.ProcessCode`(INJ/IMG/PNT/QC/RWK)로 모듈이 결정된다.
appsettings 의 `PopTerminal:ModuleCode`/`LineId`/`StationId` 는 제거됐다 — 매 로그인 선택.
모듈 코드는 `AppState.ModuleCode` 에 실리고, 라우팅과 라벨 디스패처 게이트가 이를 본다.

### 인증 흐름

**PDA 세션 배포 순서**: ① 기존 DB에 `dist/migrate_pda_bearer_session.sql` 적용(`PR_PopSession.BearerHash`·`SessionJson` 및 인덱스, 재실행 안전) → ② AMES.Api 게시본 → ③ AMES.Pda. 새 DB는 `AMES_Schema.sql`에 포함돼 있다. 기존 DB에 컬럼이 없으면 새 API의 PDA 로그인·세션 조회가 실패하므로 API보다 먼저 적용한다. 기존 세션·재고 행은 삭제하지 않는다.

- **Pop**: `PopAuthService` → `AuthRepository.FindByEmployeeNo()` → 없으면 `WorkerRepository.FindByEmployeeNo()` → `PinHasher` (PBKDF2) → `PopSessionRepository.CreateSession()`
  - POP 로그인은 두 곳을 본다: 웹 계정 작업자(`SYS_UserProfile` + `AspNetUsers`)와 POP 전용 작업자(`MD_Worker`). **사번이 겹치면 웹 계정이 이긴다.**
  - **POP·PDA 로그인에 라인 제한은 없다**(09-24) — 웹 계정의 라인 배정 컬럼 `SYS_UserProfile.AssignedLines` 와 SYS-001 라인 선택, `PopAuthService` 라인 검사를 없앴다(`dist/migrate_drop_user_assigned_lines.sql`, 신 Web·Pop·Api 배포 **후** 적용 — 구 바이너리는 이 컬럼을 SELECT 해서 먼저 적용하면 SYS-001 목록·POP 로그인이 `Invalid column name` 으로 실패). `AuthResult.LineNotAuthorized` 값은 과거 `PR_PopAuthLog` 해석용으로만 남아 있다.
  - `MD_Worker` 는 최소 구성이라 실패 카운터가 없다 — 워커는 **PIN 오류로 잠기지 않는다**.
  - **POP·PDA 로그인 성공은 웹 계정의 실패 횟수를 지우지 않는다**(10-28 — 배지·PIN 성공이 웹 비밀번호·PP-CAL PIN 실패 횟수를 0 으로 되돌려 잠금을 무력화했다). `RecordSuccessfulLogin(…, resetFailures: false)` → `SP_POP_AUTH_RecordSuccessfulLogin @ResetFailures = 0`(마지막 로그인 시각만), 횟수는 웹 로그인 성공·Admin 잠금 해제로만 지워진다. 프로시저가 새 매개변수를 받으므로 **`migrate_pop_stored_procedures.sql` 을 신 Web·Api·Pop 보다 먼저** 적용한다(구 바이너리는 새 프로시저에서 기본값 1 로 그대로).
  - **POP 이 기록하는 "누가" 는 전부 로그인 사번이다**(09-23) — 웹 계정도 GUID 가 아니라 `SYS_UserProfile.EmployeeNo`. `PopSessionRepository.CreateSession` 이 `PR_PopSession.OperatorID`·`PopSessionDto.OperatorId` 를 사번으로 채우므로 실적·LOT·PNT·QC·재작업의 `OperatorID`·`ConfirmedBy`·`InspectorID` 등 사람 컬럼과 `CreatedBy`·`ModifiedBy` 가 모두 사번이 된다(`AspNetUsers.Id` 는 `IsAdmin` 역할 조회에만 쓴다 — 역할 ID `ROLE-SYSADMIN` 보유 여부). PDA/Tablet 도 같은 `CreateSession` 을 쓰므로 API 토큰의 `OperatorId` 도 사번이다. 로그인 전 기록은 시도한 사번(`PR_PopAuthLog.CreatedBy`, PIN 실패 시 `SYS_UserProfile.ModifiedBy`), 안돈은 감사 컬럼 = 로그인 사번 · 배지를 찍은 사람은 `AckedBy`·`CalledBy`·`ArrivedNo`·`TechnicianID`·`ReportedBy` 에 남는다. 그 이전 행은 GUID 가 섞여 있다. 사번은 웹 계정·워커를 통틀어 전사 유일해야 한다(SYS-001 사용자 저장이 두 테이블과의 중복을 거부하지만 DB 제약은 없다).
  - `AMES.Api` 의 `/api/auth/login` 도 같은 서비스를 쓰므로 **PDA 도 워커 로그인을 받는다.**
  - POP 로그인 화면은 시리얼 스캐너(`ScannerService`)로 사원증 QR 을 받으면 `AuthMethod.Badge` 로 **PIN 없이 즉시 로그인**한다. 라인·스테이션 미선택, 픽커 열림, 로그인 진행 중에는 스캔을 무시한다.
  - 사원증 QR 발행 양식은 **`EOS*사번*이름`** 세 토큰이고 `AMES.Devices.BadgeScanParser` 가 정본이다(단위 테스트 `AMES.Pop.Tests/BadgeScanParserTests`). 이 양식이 아니면 스캔값 전체를 사번으로 본다 — 구 사번-only QR 과 웹 계정 배지가 계속 동작하게 하려는 것이며, 그 경로는 자동 등록 대상이 아니다.
  - **EOS 양식으로 읽히면 모르는 사번은 그 자리에서 `MD_Worker` 에 만들어진다**(`EmployeeName`=배지의 이름, 없으면 사번 / PIN 없음 / `CreatedBy`=본인 사번 — 09-23 이전 행은 `'POP-SCAN'`, MD-032 는 둘 다 배지 등록으로 표시). 로그인 화면 스캔에서만 동작하며 PDA/API 는 종전대로 등록된 사람만 받는다. 즉 **EOS 양식 QR 을 인쇄할 수 있으면 누구나 계정을 만들 수 있다** — 배지 발급을 통제할 것. INSERT 전용이라 `ActiveFlag=0` 인 행은 재스캔으로 되살아나지 않고, 관리자가 고친 이름도 덮이지 않는다. **그래서 MD-032 는 작업자를 지우지 않고 「사용 안 함」(ActiveFlag 0, `WorkerRepository.Deactivate`)으로만 둔다**(10-13 사용자 결정 — 행을 지우면 그 사람이 배지를 찍는 순간 PIN 없는 새 계정으로 다시 생겼다). 다시 쓰려면 수정 창의 활성 체크박스를 켠다.
  - **`PinHash` 가 없는 워커는 배지 로그인 직후 PIN 설정을 강제한다** — 4자리를 두 번 입력해 일치해야 저장(`ModifiedBy`=본인 사번)되고 작업 화면으로 넘어간다. 건너뛸 수 없다: PIN 이 없으면 스캐너가 죽었을 때 그 사람은 들어올 방법이 없다. 자동 등록분뿐 아니라 등록 화면에서 PIN 없이 만든 워커도 대상이다.
  - 화면이 이걸 판단하는 근거는 `PopSessionDto.IsWorker` · `HasPin` 이고 `PopSessionRepository.CreateSession` 이 채운다. **PIN 설정 전에 `PR_PopSession` 행은 이미 생긴다** — 오버레이 상태로 자리를 뜨면 열린 세션이 남고 만료시각으로만 정리된다.
  - **POP 창을 닫는 것도 로그아웃이다**(10-28, `PopBlazorForm.CloseSessionOnExit`): 사유 `APP_CLOSE` 로 세션을 닫고 라벨 워터마크를 남긴다(최대 3초 — 못 끝내거나 DB 가 끊겼으면 오프라인 저널에 올려 다음 실행의 복구가 닫는다).
- **Api**: `POST /api/auth/login` → `TokenStore.Issue()` → Bearer 헤더 검증 (`BearerAuth` 미들웨어)
- **Web**: ASP.NET Identity, `ApplicationDbContext` (EF Core, Identity 테이블 전용)
  - **화면 읽기 권한은 `MainLayout` 이 공통으로 검사한다**(09-29) — 라우터가 정적이라 화면 이동마다 레이아웃이 서버에서 먼저 돌고, 내부 계정이 `SYS_Screen` 에 등록된 화면(하위 경로 포함, PORTAL 제외)을 R 없이 열면 `/unauthorized`(`PermissionService.CanOpen`). 새 화면도 `SYS_Screen` 에 등록하면 자동으로 막히고, 미등록 경로는 막지 않는다. 화면별 `IsVisible` 검사는 남아 있어도 무방하며 E/A 버튼 게이트는 여전히 화면 몫이다.
  - **권한은 3자리 R(읽기)·E(수정)·A(승인)**(10-10 사용자 결정) — ① **화면 기본 권한 `SYS_Screen.PermissionCriteria`**(varchar(10), `LidLabel` 다음, 기본 `___`) = 그 화면에 있는 기능: 자리마다 `_`(있음)·`X`(없음), **읽기는 항상 `_`**(화면을 숨기려면 표시를 끈다). SYS-003 목록 「기본 권한」 열과 등록·수정 창의 체크박스(읽기 고정·수정·승인)로 관리하고, 수정 저장 때 **그 화면의 역할 권한도 같은 트랜잭션에서 맞춘다**(X 가 된 자리는 부여돼 있어도 X, 다시 생긴 자리는 `_`, 남는 부여가 없는 행은 삭제 — `SysRepository.UpdateScreen`). ② **역할 권한 `SYS_RolePermission.PermissionLevel`** = 부여: 자리마다 글자·`_`(미부여)·`X`(기능 없음), 예 `REX` `R_X` `RXX` `R_A`. SYS-004 는 화면 기본 권한으로 없는 기능의 체크박스를 끄고(툴팁 `SYS.Rbac.NoFeature`) 일괄 선택에서도 건너뛰며, **수정·승인을 켜면 읽기도 켜고 읽기를 끄면 셋 다 끈다**(10-12 — 읽기 없는 수정·승인은 화면을 못 열어 쓸모가 없다, 칸·열 일괄 공통 `PermissionSlots.Toggle`, 저장하는 `Compose` 도 수정·승인이 있으면 읽기를 붙인다). 열어 둔 SYS-004 는 SYS-003 저장 알림(`ScreenCatalogNotifier`)을 받으면 화면 기본 권한을 다시 읽어 체크박스를 맞추고(저장 안 한 편집은 두고 없어진 기능 칸만 풀며, 편집이 없으면 SYS-003 이 맞춘 권한 행도 다시 읽는다 — 안내 `SYS.Rbac.Msg.CriteriaChanged`), 알림이 오지 않는 변경(다른 서버의 Web·DB 직접 수정)은 역할을 고를 때마다 화면·권한 행을 다시 읽어 맞춘다(10-12). **저장은 역할을 고를 때 읽은 값(기준)과 달라진 화면만 보낸다**(10-14 — 전에는 화면 전체를 보내 체크가 없는 화면의 권한 행을 지웠기 때문에, 조회가 실패해 빈 체크 상태로 저장하거나 두 사람이 같은 역할을 고치면 다른 화면 권한이 사라졌다; 규칙 정본 `AMES.Data.Services.RolePermissionDiff`, 테스트 `RolePermissionDiffTests`). 권한·화면 조회가 실패하면 매트릭스 위에 안내와 「다시 불러오기」를 보이고 체크박스·저장을 막는다(저장 처리 첫 줄도 확인). 감사 로그는 바뀐 화면만 전/후로 남긴다. **권한을 다시 줄 수 있는 두 화면 SYS-003(`sys/screens`)·SYS-004(`sys/rbac`)는 잠그지 못한다**(10-12 사용자 결정, 정본 `AMES.Data.Services.ProtectedScreens` — 화면은 주소로 가른다): System Administrator(`ROLE-SYSADMIN`)의 두 화면 읽기·수정은 SYS-004 에서 체크된 채 꺼진 칸(툴팁 `SYS.Rbac.AdminLocked`)이고 `SaveRolePermissions` 도 넘어온 값과 관계없이 남긴다. ## 화면 로딩 구조 개선 (11-19)

- **공용 캐시 `ScreenAccessCache`(싱글톤)**: 화면 목록(SYS_Screen)·역할 권한·사용자 역할을 서버 전체가 함께 쓴다. `PermissionService`·`MenuCatalog`·`AmesPageHeader`·`TopBar` 가 여기서 읽는다(전에는 화면 이동마다 SYS_Screen 3번·역할 2~3번 DB 조회). `ScreenCatalogNotifier.Notify()` 로 버전이 바뀌면 바로, DB 직접 수정은 60초 안에 반영. 저장·승인 직전 `RecheckEditAsync`/`RecheckApproveAsync` 는 `fresh` 로 캐시를 건너뛴다. SYS-003·SYS-004 같은 관리 화면은 DB 를 직접 읽는다. 반환 목록은 공유본이라 고치지 말 것.
- **화면 렌더 모드 `AmesRender.Server`** = `InteractiveServerRenderMode(prerender:false)`: 새 화면(@page)은 `@rendermode AmesRender.Server` 를 쓴다. 미리 그리기가 켜져 있으면 OnInitialized(DB 조회)가 두 번 돌고 그동안 화면이 눌리지 않았다. 예외: `PersistentComponentState` 를 쓰는 LocationMap(WH·FG)과 레이아웃 부품(NavMenu·TopBar·SessionGuard·RadzenComponents)은 `InteractiveServer` 그대로.

- **앱 전체 실시간 연결(D, 11-19)**: `App.razor` 가 `Routes`·`HeadOutlet` 에 `AmesRender.Server` 를 준다(`HttpContext.AcceptsInteractiveRouting()` 일 때). 화면 이동은 연결 안에서 끝나고 레이아웃·메뉴는 유지된다. `[ExcludeFromInteractiveRouting]` 화면(Account 전체·`/Error`·`/portal/login`·`/portal/error`)은 정적 렌더로 남고, 연결 안에서 그리로 가면 전체 새로고침된다.
  - **권한 검사**: `MainLayout.OnParametersSetAsync` 가 화면을 옮길 때마다(새 Body) 검사한다 — 다른 화면이면 판정 전까지 본문을 그리지 않고, 쿼리만 바뀐 같은 화면은 다시 만들지 않는다. 판정 순번(`_checkSeq`)으로 늦게 끝난 앞 화면 판정은 버린다. 비로그인 요청은 지금처럼 엔드포인트 인증에서 302(로그인)로 막힌다.
  - **내부↔포탈 경계**: `CircuitBoundaryGuard`(Routes) 가 `/portal` 안팎을 넘는 이동을 전체 새로고침으로 바꾼다(연결 경로·쿠키가 다름).
  - **세션 유지·만료**: 이동이 HTTP 요청을 만들지 않으므로 `js/nav-keepalive.js` 가 주소가 바뀔 때 `/keep-alive` 를 보낸다(1분에 한 번까지). 응답이 로그인으로 돌려보내지면 새로고침해 로그인 화면으로 보낸다.
  - 진행바(`nav-progress.js`)는 `enhancedload` 대신 본문 변경(MutationObserver)으로 끝난다. 첫 접속 로딩 표시는 `App.razor` 의 `#ames-boot`.
